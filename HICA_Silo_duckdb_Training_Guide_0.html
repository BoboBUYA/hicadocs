Important: Do not confuse the Silo Console port 9101 with the S3 API port 9100. DuckDB uses localhost:9100. The Console is for browsing; it is not a SQL editor.

3. Install DuckDB

On Windows, there are two common ways to use DuckDB.

Option A — DuckDB CLI installer (PowerShell)

To install the DuckDB command-line tool on Windows, open PowerShell and run:

# Install DuckDB CLI
powershell -NoExit -ExecutionPolicy Bypass -Command "irm https://install.duckdb.org/install.ps1 | iex"

After the installer completes, open a new PowerShell window and run duckdb to start the DuckDB SQL prompt. If PowerShell cannot find the command, restart the terminal so it reloads the updated PATH.

Option B — Python package

Activate the Python virtual environment you want to use, then install DuckDB:

python -m pip install --upgrade pip
python -m pip install duckdb

Start Python and check the installation:

python
>>> import duckdb
>>> duckdb.sql("SELECT version()").show()

Option C — Start the DuckDB CLI

If you installed the DuckDB CLI, open PowerShell in the folder containing duckdb.exe, or make it available on your PATH, then run:

duckdb

At the DuckDB prompt, enter SQL statements directly. The successful commands in this guide use DuckDB SQL syntax.

The Python package and CLI are separate ways to access DuckDB. If you installed only the Python package, run SQL through Python (for example, duckdb.sql(...)) or install the CLI separately.

4. Check that Silo is running and find its connection details

Check Docker containers and published ports (PowerShell)

docker ps --format "table {{.Names}}\t{{.Ports}}"

In this setup, the relevant container was hmis-silo-silo-1, with host ports 9100 and 9101.

Check the MinIO API health

curl.exe http://localhost:9100/minio/health/live

A successful health response indicates the API is reachable. If it fails, check that the container is running and that the port mapping is still present.

Find the configured MinIO credentials

Check the container environment without publishing or sharing the secret values:

docker inspect hmis-silo-silo-1 --format '{{range .Config.Env}}{{println .}}{{end}}' |
  Select-String 'MINIO_ROOT_USER|MINIO_ROOT_PASSWORD'

If the variables are not shown, inspect the Compose file and the project's .env file for the MinIO environment configuration. Keep the access key and secret key private.

Inspect MinIO Client aliases

docker exec hmis-silo-silo-1 mc alias list

The alias output we inspected showed a local alias pointing to http://localhost:9000 inside the container, but its AccessKey and SecretKey were blank. The gcs and s3 entries showed placeholder credentials, not working Silo credentials.

Inside the MinIO container, the API is on port 9000. From Windows, Docker publishes that same API on localhost:9100. This is why the endpoint differs depending on where the client runs.

5. Configure DuckDB to connect to Silo

Open DuckDB and install/load its httpfs extension. This extension provides remote-file and S3-compatible access.

INSTALL httpfs;
LOAD httpfs;

Create a DuckDB S3 secret using the actual MinIO credentials. Run this once per DuckDB session (or configure a persistent secret if that suits your security policy):

CREATE OR REPLACE SECRET silo_secret (
    TYPE S3,
    KEY_ID 'YOUR_MINIO_ACCESS_KEY',
    SECRET 'YOUR_MINIO_SECRET_KEY',
    REGION 'us-east-1',
    ENDPOINT 'localhost:9100',
    URL_STYLE 'path',
    USE_SSL false
);
  • Replace the two credential placeholders with the configured MinIO access key and secret key.
  • Use ENDPOINT 'localhost:9100' when DuckDB runs on the Windows host.
  • Use URL_STYLE 'path' for a typical MinIO path-style bucket URL.
  • Use USE_SSL false for the local HTTP endpoint shown in this setup.
  • The region value must match the MinIO configuration if a specific region has been configured; us-east-1 is commonly used as a default.
Credential safety: Never paste real access keys or secret keys into chat, screenshots, source control, or shared documents. Avoid saving credentials in scripts committed to Git.

7. Query the Landing layer (raw files)

The Console link supplied during the session pointed to this raw child-health data-value object:

s3://hmis-datalake/landing/dhis2/data_values/
  dataset=child_health/
  data_set_id=BfMAe6Itzgt/
  run_id=20261103T124700Z/
  mode=full/
  2026-11.json.gz

DuckDB query for that exact raw JSON.GZ object:

SELECT *
FROM read_json_auto(
  's3://hmis-datalake/landing/dhis2/data_values/dataset=child_health/data_set_id=BfMAe6Itzgt/run_id=20261103T124700Z/mode=full/2026-11.json.gz'
)
LIMIT 100;

This is a Landing-layer query. It reads the raw JSON object, not the dbt staging Parquet model.

8. Query the Staging layer (Parquet)

The object listing showed the following staging models:

  • stg_dhis2__category_option_combos.parquet
  • stg_dhis2__data_elements.parquet
  • stg_dhis2__data_set_org_units.parquet
  • stg_dhis2__data_sets.parquet
  • stg_dhis2__data_values.parquet
  • stg_dhis2__organisation_units.parquet

Use this query to select data values from the staging model:

SELECT *
FROM read_parquet(
  's3://hmis-datalake/staging/dhis2/stg_dhis2__data_values.parquet'
)
LIMIT 100;

Count the rows:

SELECT COUNT(*) AS total_records
FROM read_parquet(
  's3://hmis-datalake/staging/dhis2/stg_dhis2__data_values.parquet'
);

Inspect the actual column names and data types before writing more specific queries:

DESCRIBE
SELECT *
FROM read_parquet(
  's3://hmis-datalake/staging/dhis2/stg_dhis2__data_values.parquet'
);

After confirming the schema, query only columns that actually exist. For example, if the model contains period:

SELECT
  period,
  COUNT(*) AS total_records
FROM read_parquet(
  's3://hmis-datalake/staging/dhis2/stg_dhis2__data_values.parquet'
)
GROUP BY period
ORDER BY period DESC;

9. Querying dbt Intermediate Parquet models

If your dbt project writes Intermediate models to the Silo bucket as Parquet files, you can query them directly with DuckDB in the same way as the Staging models. The exact Intermediate prefix and filenames were not visible in the object-listing output shared during this session, so first discover their actual paths.

Find Intermediate model files

SELECT *
FROM glob('s3://hmis-datalake/intermediate/**');

If your project uses a different prefix (for example, marts/ or a nested dbt target folder), search the bucket listing for the actual Parquet object paths:

SELECT *
FROM glob('s3://hmis-datalake/**')
WHERE file ILIKE '%intermediate%'
   OR file ILIKE '%int_%'
   OR file ILIKE '%\.parquet';

Once you have confirmed the exact object path, query one Intermediate model:

SELECT *
FROM read_parquet(
  's3://hmis-datalake/ACTUAL_INTERMEDIATE_PREFIX/ACTUAL_MODEL.parquet'
)
LIMIT 100;

Inspect the Intermediate model schema

DESCRIBE
SELECT *
FROM read_parquet(
  's3://hmis-datalake/ACTUAL_INTERMEDIATE_PREFIX/ACTUAL_MODEL.parquet'
);

Count records

SELECT COUNT(*) AS total_records
FROM read_parquet(
  's3://hmis-datalake/ACTUAL_INTERMEDIATE_PREFIX/ACTUAL_MODEL.parquet'
);

Query multiple Parquet files (only when schemas are compatible)

SELECT *
FROM read_parquet(
  's3://hmis-datalake/ACTUAL_INTERMEDIATE_PREFIX/*.parquet',
  union_by_name = true
)
LIMIT 100;
Important: Intermediate models are not the same as the raw Landing files or the Staging models. Use the actual prefix and filenames produced by your dbt configuration. Do not assume that an intermediate/ folder exists until it appears in the Silo object listing. The union_by_name option is useful only when combining files with differing but compatible column layouts; querying one model file at a time is safer for initial inspection.

10. Troubleshooting checklist

SymptomLikely causeWhat to check
Connection refused / cannot connectContainer stopped, wrong host port, or API not reachableRun docker ps; test curl.exe http://localhost:9100/minio/health/live.
Access denied / invalid access keyWrong or missing MinIO credentialsCheck MINIO_ROOT_USER and MINIO_ROOT_PASSWORD in the container configuration or Compose .env.
Bucket or key not foundIncorrect bucket name or object pathRun glob('s3://hmis-datalake/**') and copy the exact object key.
DuckDB says S3 support is unavailablehttpfs is not installed or loadedRun INSTALL httpfs; then LOAD httpfs;.
File format / JSON parsing errorWrong reader for the object format or unexpected JSON structureUse read_json_auto() for JSON/JSON.GZ and read_parquet() for Parquet. Inspect a small sample.
Column does not existAssumed column names do not match the dbt modelRun DESCRIBE SELECT * FROM read_parquet(...) first.
Glob returns no objectsIncorrect prefix, bucket, or permissionsTry the known bucket root and progressively narrower prefixes.
Slow query / large downloadLarge object or broad wildcard scans many filesStart with one exact object and a small LIMIT; avoid scanning the whole bucket unnecessarily.

11. Key distinctions to remember

  • Silo / MinIO is object storage. It stores objects; it is not itself a SQL database.
  • MinIO Console (localhost:9101) is used to browse buckets and files.
  • MinIO S3 API (localhost:9100) is the endpoint DuckDB uses from the Windows host.
  • DuckDB is the SQL engine used here to query remote JSON and Parquet objects in place.
  • Landing contains raw ingested files; Staging contains the dbt-generated Parquet models observed in this bucket.
  • ClickHouse is a separate analytical database in this Docker stack. Its ports are not the Silo S3 endpoint.

12. Quick-start command sequence

After DuckDB is installed and the Silo credentials are available, this is the short sequence to reconnect and query the staging data values:

-- DuckDB SQL
INSTALL httpfs;
LOAD httpfs;

CREATE OR REPLACE SECRET silo_secret (
    TYPE S3,
    KEY_ID 'YOUR_MINIO_ACCESS_KEY',
    SECRET 'YOUR_MINIO_SECRET_KEY',
    REGION 'us-east-1',
    ENDPOINT 'localhost:9100',
    URL_STYLE 'path',
    USE_SSL false
);

-- Confirm bucket/object visibility
SELECT *
FROM glob('s3://hmis-datalake/**');

-- Query the dbt staging data-values model
SELECT *
FROM read_parquet(
  's3://hmis-datalake/staging/dhis2/stg_dhis2__data_values.parquet'
)
LIMIT 100;
